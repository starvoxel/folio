# PRD area I: Importing

Part of [Closeout](month-end-review.md). Each CSV belongs to one account; nothing is added until the user confirms a preview.

| ID    | Requirement                                                                                                                                                                                                                                                 | Priority |
| ----- | ----------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- | -------- |
| I1.1  | One or more CSVs can be added by drag-and-drop or file dialog                                                                                                                                                                                               | must     |
| I1.2  | The provider is detected by matching column headers and formats against known profiles                                                                                                                                                                      | must     |
| I1.3  | Built-in profiles at launch: RBC, TD, Tangerine, EQ Bank, Questrade, CTFS                                                                                                                                                                                   | must     |
| I1.4  | An unmatched file prompts a one-time column mapping (date, description, amount or debit/credit, optional balance) that is saved as a new provider profile                                                                                                   | must     |
| I1.5  | A provider profile records which sign direction means money out; the preview shows the result so a wrong setting is caught before import                                                                                                                    | must     |
| I1.6  | The app suggests the account last used with the detected provider; the user confirms or picks another                                                                                                                                                       | must     |
| I1.7  | The preview shows every row with its suggested category                                                                                                                                                                                                     | must     |
| I1.8  | Likely duplicates of already-imported transactions are flagged in the preview and each can be skipped or kept                                                                                                                                               | must     |
| I1.9  | Only posted transactions import; pending rows are skipped                                                                                                                                                                                                   | must     |
| I1.10 | Each transaction is filed under its own date, so one file may add to two months                                                                                                                                                                             | must     |
| I1.11 | Rows dated in a locked month are listed and skipped; the rest of the file still imports                                                                                                                                                                     | must     |
| I1.12 | Each account shows "covered through <date>", the latest date of its imported data                                                                                                                                                                           | must     |
| I1.13 | If a new file starts after the account's covered-through date, the app warns that transactions may be missing                                                                                                                                               | must     |
| I1.14 | On import, rules apply and transfer pairs are matched ([C](month-end-review-categorization.md), [T](month-end-review-transfers.md))                                                                                                                         | must     |
| I1.15 | An entire import can be undone as one step; if the import added rows to a month that has since been closed, undo removes only the rows in still-open months                                                                                                 | must     |
| I1.16 | An unreadable or malformed file shows a clear error naming the problem row or column, and adds nothing                                                                                                                                                      | must     |
| I1.17 | A CSV balance column, when present, is kept as a known balance for month-end balance calculation ([N](month-end-review-net-worth.md))                                                                                                                       | should   |
| I1.18 | Provider profiles can be viewed, edited and deleted in Settings                                                                                                                                                                                             | should   |
| I1.20 | The preview flags a row as suspicious with a stated reason when a local check trips: a new merchant with a large amount, repeated charges in a short window, an amount far above that merchant's norm, or foreign-currency or unusual-merchant-code markers | must     |
| I1.21 | Flagging runs offline on the user's data only and never blocks or delays an import                                                                                                                                                                          | must     |
| I1.22 | A suspicious flag can be dismissed, or the transaction marked as confirmed fraud; confirmed fraud is excluded from spending and income totals and carries a note; a transaction in a locked month can be marked only through the guarded reopen             | must     |
| I1.23 | Undismissed suspicious flags continue into the month's review queue ([M](month-end-review-close.md))                                                                                                                                                        | must     |
| I1.24 | The thresholds for each check are set in Settings, with defaults                                                                                                                                                                                            | should   |
| I1.25 | The account chosen in the import dialog must use the file's detected provider; a mismatch blocks the import with an error and adds nothing                                                                                                                  | must     |

Deferred, not requirements: PDF statement import, which will reuse the preview step. Flow and rules: choose files → detect provider (or map columns) → pick account → preview → import. Files are read locally and never uploaded.

Assumptions (not in the write-up): I1.20 to I1.24 come from the review comment on flagging possibly fraudulent transactions (local heuristics chosen in review; exact thresholds and defaults are defined at planning, and excluding confirmed fraud from totals was confirmed by Jeremy after prototyping); I1.25 comes from the updated prototype; I1.16 (clear error on a malformed file, nothing added) and I1.18 (profiles editable in Settings) are proposed; "likely duplicate" means same account, date, amount and normalized description as an existing transaction; the precise rule is settled at planning. Re-importing an identical file therefore flags every row. The I1.15 rule for imports that span a since-closed month follows architecture decision AD-5 (2026-11-05).
